## Verify before any merge

For a scoped change on main, preserve an archive tag for any divergent source
tip first, start from a clean candidate and the correct base, then run the
native gate:

~~~sh
scripts/auto-loop/gate.sh native <candidate-worktree> origin/main
~~~

The gate is the local merge authority. It includes the memory preflight,
configured native build, deterministic selftest battery, CTest, verification
scripts, conformance, and UI checks. When a focused change warrants it, also run
the relevant focused suite (including MoshTests for Re-Imagine) and record its
result with the change. Hosted CI and screenshots are useful signals, not a
replacement for the local gate or owner acceptance.

Run the built application's --selftest three times and --selftest-undo when
performing a final baseline/release-style verification. Do not carry forward the
temporary MOSH_MAX_CODEX_CHILDREN=1000 consolidation override as a standing
policy; the normal gate limits apply outside this one-time maintenance work.

## Hard rules

- macOS / Apple Silicon is the owner-validation surface; the Windows +
  NVIDIA/CUDA path remains additive.
- Every user-visible mutation uses MoshOps: validate → Tracktion undo
  transaction → events → JSONL log → result envelope. There is one undo system
  (Tracktion's); machine and monitoring preferences remain undoable:false.
- Snapshot and event changes are additive. The WebView and agent do not mutate
  Tracktion directly.
- Heavy generative work stays out of the audio thread. The real-time RAVE route
  is build-gated behind MOSH_ENABLE_ANIRA and is off in the default build.
- Do not put secrets in the repository, logs, or commits. Runtime keys belong
  in ~/.config/mosh/env (mode 600); inspect staged changes before pushing.
- Tutorial/source media is processed locally only and is never redistributed.
- Do not convert a native test, CI result, dashboard, screenshot, or host smoke
  into a claim of audible output, Live behavior, iPhone reachability, or
  physical-device recovery.
