## The 2×2 that disentangled the r5 regression

| | v1 prompt | cal2 prompt |
|---|---|---|
| hd 4-bit fuse | 64% | 64% |
| 8-bit + naive adapter | (moot) | 36% |

The 36% crater was the SERVE, not the prompt. Naive `--adapter-path` overlay of the
bf16-trained LoRA on the 8-bit base is itself a train/serve precision mismatch — the hd
fused build exists precisely because of this class of failure, and the rule cuts both
ways. A real precision upgrade = re-running the attn-overlay fuse recipe against the
8-bit base (mosh-loras/pmetal tooling), not a serve flag.

## Lessons with legs

1. **Calibration prose is for generalists.** It lifted both untuned cloud models
   (+12/+16) and did nothing to the SFT-tuned specialist, whose training already encodes
   the discipline. Ship cal2: helps the cloud lane, costs the local lane nothing.
2. **r5's remaining misses are SFT-coverage gaps** (drum-kit domain asks, multi-step
   lyric flows, one persistent create_section ambiguity violation) — the lever for 20/25
   is a targeted training-data pass, not more prompting.
3. **Dense-27B+ is architecturally out** on this hardware for interactive use: measured
   146–169 s/call at real prompt scale vs r5's 1.7 s. No quant/conversion/drafter closes
   a ~10x dense-vs-MoE compute gap. Consumer-distill class: MoE / small-dense.
4. At equal 64%, r5 wins the product decision on latency and cost alone — and it is the
   only entrant whose score has a known, ownable improvement path.
