# Plan — Restart: real recipes as the generation substrate (retrieval / imitation)

## Context

The owner listened to the latest beats (now with real samples + a real pitched 808) and said they still "sound bizarre… they all sound the same… the 808 plays an eighth-note pattern like you're treating it like a hi-hat… this is guessing randomly, we need to start from a place of *knowing*." That is an accurate readout of the architecture, confirmed by reconstruction of the specs + a unanimous 4-model frontier panel (OpenAI / Gemini / Anthropic / xAI):

- **Two pipelines that never connect.** Beats are generated by `ui/src/agent/beatBuilder.ts` filling **3 hardcoded genre templates** with LLM notes, optimized by GEPA to **maximize a hand-written rules grader** (`recipeVerifier`). The teardown→recipe pipeline that was *designed to supply real-producer taste* is built but **has never produced a single real recipe** (disk check: one `recipe.schema.json`, **0 extracted `.mid`**, 0 tutorial reconstructions; the "anchor corpus" came from the owner's own FLPs + synthetic grooves).
- **Both taste signals failed structurally.** The learned audio reward came back **ρ≈0** ("renderability-dominated, not musical-taste"). The rules verifier is **hardcoded taste by construction** — GEPA pushed it 0.79→0.97 while the music got worse (Goodhart). Owner's own evidence: concrete real worked-examples lifted inference **+30pp/+12pp**; intent-only rule cards gave **zero**.
- **The two bugs are one root cause:** the agent guesses inside a hand-built box scored by a hand-built checklist — *nothing in the loop has ever seen a real beat.* "Same-y" = variance only in template slots. "808-as-hi-hat" = every pitched element is a generic note-stream on a **shared onset grid**, so the 808 inherits the hat's rhythmic prior. Today's `Recipe` model can't even represent a bassline (notes live in an external pointer; 808 compiles to a *drum* track).

**Decision (owner + panel):** make **mined real recipes the generation substrate** via retrieval/imitation — ground every beat in real-producer patterns/params/sample-choices, generate by **recombination + transposition** of real per-element motifs, **not** template-fill + rules-optimization. **Freeze** the RL/reward path (don't delete). **Demote** the rules verifier to a validity *gate*. Owner choices: **hand-verify a small clean seed set first**; **v1 genre = trap / melodic-trap** (FL Studio, MIDI-from-screen already live); defer sample-chop/boom-bap (~60% unencodable).

**Outcome:** a request produces a MoshOps program **recombined from real recipes** — drums from one, an 808 phrase (real durations, root-following, syncopated ≠ hats) from another, chords from a third, transposed into one key/tempo. The owner hears beats that are *musically different from each other* and *sound like real beats*, because the generation distribution **is** the set of real beats.

---

## The architectural change (one sentence)

Replace `beatBuilder` (template-fill) + `recipeVerifier`-as-optimizer with: **Recipe Library (real, motif-bearing) → retrieve k → recombine + transpose → compile to MoshOps → render**, with the verifier demoted to a hard validity gate and RL frozen.

## The spine the panel converged on

- **Granularity = per-element motifs** (reject whole-beat clone *and* per-note guessing). Generalization = cross-recipe recombination of **transposable** motifs (relative pitch vs. key root, onsets in beats).
- **Bassline = rhythm × pitch-function, stored separately.** Rhythm: sparse onsets + **real note durations** (808 sustains 1–4 beats, not 1/8 stabs) + a syncopation profile **not shared with hats**. Pitch: a *function of harmonic context* (root-following + explicit glide/portamento). Transplant a real 808 motif → "straight eighths" is structurally impossible.
- **Generative freedom in v1 = recombination + transposition only**, not free invention.

## Phase 0 — Prove the generation half on a hand-verified seed (THE make-or-break gate)

Everything else is gated on Phase 0. No mining-at-scale, no app integration, until Gate C passes.

**0.1 — Give recipes a musical body.** Extend `service/teardown/recipe.py` (+ regenerate `recipe.schema.json`, update `recipe_test.py`):
- Inline **note events** per element: `{pitch, start_beats, duration_beats, velocity}` (stop relying on the external `midi_ref` pointer — keep it as optional provenance).
- A per-element **motif layer**: richer `role`, rhythmic signature (onset grid + density), melodic contour, harmonic function; stored **transposable** (relative to key root).
- A **bass/808 sub-model**: `sustain_ratio`, `glides[]`, `kick_alignment`, `root_follows` (binds to the chord element). This is the field that makes the 808 bug unrepresentable.
- Keep `{value, confidence, evidence}` + `extra='forbid'`; partial recipes stay first-class.

**0.2 — Make the compiler emit a full, real program.** Extend `service/teardown/render/compile.py` + `execute.py`:
- Emit inline notes (`add_note` from the new note events) instead of deferring to `midi_ref`.
- **Melodic-808 path:** an `808`/`bass` element compiles to an **audio/sampler track** with `assign_sample mode:"melodic"` (root note, sustained durations, **monophonic via non-overlapping authoring**) — NOT a drum track. Remove `808` from the drum-track branch for melodic basslines.
- Bind a matched palette sample per element (reuse the existing sample palette / `SampleIndex`); load real synth + params where present.
- Golden test (`compile_test.py`) for the new emission incl. the 808 path.

**0.3 — Author the seed set (~12–20 clean trap/melodic-trap recipes).** Cheapest reliable path per recipe: run the existing extractor on a known FL tutorial → **hand-correct** the motifs/params (or directly transcribe canonical patterns where the extractor is too rough). Each stored as `recipe.json` with real per-element motifs + a correct 808 phrase. Small authoring/QA harness (reuse `--run-script` render + numpy WAV checks).

**0.4 — GATE A (fidelity, owner ear).** Each seed recipe reconstructs → renders to WAV → A/B vs. the source tutorial audio. Bar: *"does the reconstruction sound like that beat?"* If no → fix extraction/representation before proceeding (panel's #1 risk: corrupted recipes = real-flavored garbage).

**0.5 — Build the retrieval + recombination generator** (new module; supersedes `beatBuilder` for this path). Parse request (genre/tempo/key/mood) → retrieve 3–8 recipes/motifs by tags + palette compatibility → choose a backbone + **transplant per-element motifs** from others → **transpose** to one key/tempo → enforce **binding rules** (808 root-follows the chosen chords; bass onset grid ≠ hat grid) → emit MoshOps via the 0.2 compiler. Motif retrieval = lightweight symbolic embedding (role + rhythmic signature + contour + tempo band).

**0.6 — GATE B (conditioning).** Force-retrieve ONE recipe; require the emitted program to match **≥70% of its note events**; renders non-silent. Proves the agent actually *uses* the recipe rather than hallucinating around it.

**0.7 — GATE C (the verdict, owner ear).** Blind A/B pack (reuse `buildValidityPack.mts` harness): per group, **retrieved-adapted** vs. **current-template** vs. **exact reconstruction**, scored on *musically distinct* + *would keep*. **Retrieved-adapted must decisively beat templates.** This gate decides whether the whole approach is right; if it fails, fix the recipe schema/representation before any scaling or training.

## Phase 1 — Automate + harden the miner (only after Gate C)

Make `video2recipe` + `render` reliably produce **Gate-A-passing** recipes from FL trap/melodic-trap tutorials; grow the library to **~30–50 recipes** (panel: imitation needs tens, not thousands). Each recipe must pass Gate A (fidelity) before entering the library. Prototype-with-20 → judge-at-30–50.

## Phase 2 — Integrate into the live agent + grow

Wire the retrieval-recombination generator as the agent's beat path in the app (replace `beatBuilder`), behind the validity gate. Grow the corpus; richer recombination. (A learned *preference* layer is revisited only much later, once real owner preference labels exist — explicitly deferred.)

## The validity gate (demoted `recipeVerifier`)

Strip every taste dimension (velocity-variance, contour scoring, density targets). Keep as a **hard filter only**: in-key, on-grid (where intended), renderable, real samples — **add an 808/bass plausibility check** (sustained durations, not hi-hat density). `ui/src/agent/recipeVerifier.ts` + `service/teardown/flywheel/recipe_verifier.py`, parity-locked. **GEPA-against-the-verifier is banned; `MOSH_RL_REWARD=recipe` path frozen.**

## Critical files

- `service/teardown/recipe.py` (+ `recipe.schema.json`, `recipe_test.py`) — musical-body extension (notes, motifs, bass sub-model).
- `service/teardown/render/compile.py` + `execute.py` (+ `compile_test.py`) — inline notes, melodic-808, sample/plugin binding.
- **NEW** retrieval+recombination generator (offline in `service/` for the Phase-0 proof; wired to the agent in Phase 2).
- `ui/src/agent/recipeVerifier.ts` + `service/teardown/flywheel/recipe_verifier.py` — strip to validity gate + 808 check (parity-locked).
- Seed-authoring + blind-A/B harness — reuse `ui/scripts/rl/buildValidityPack.mts` + the `Mosh --run-script` render-to-WAV harness (`scripts/verify-hardware/`).
- `ui/src/agent/beatBuilder.ts` — kept until the Phase-2 swap, then retired from the beat path.

## Verification

- **Gates A/B/C** are the real verification (owner ear for A/C; ≥70% event-match for B).
- Automated: schema round-trip (`recipe_test.py`), compiler golden (`compile_test.py`), validity-gate TS↔Python parity, render-to-WAV **non-silence + 808-sustain** check (no straight-eighths bass), 3× deterministic where applicable.
- The melodic-808 `assign_sample mode:"melodic"` exists only in the **debug binary** (not `/Applications/Mosh.app`) — the proof uses the debug binary; Phase 2 needs a rebuild/deploy.

## Out of scope / deferred (do NOT build)

- RL / reward training (**frozen**, not deleted), and any GEPA-against-verifier optimization.
- The `#55` reward-validity/preference pack *as a taste optimizer*, and `#56` BT taste model — deferred until there's a proven generator + real preference labels.
- Sample-chop / boom-bap mining (~60% unencodable); Ableton/Logic MIDI-from-screen (FL first).
- Mining at scale before Gate C passes.
