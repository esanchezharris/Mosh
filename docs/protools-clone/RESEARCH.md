## Evidence-backed layout contract

- A fixed Edit Window toolbar sits above the timeline and groups modes, tools, counters, Grid, and Nudge.
- A Marker ruler plus one or more timebase rulers stack directly above the lanes. Mosh exposes Markers, Bars+Beats, Timecode, Minutes:Seconds, and Samples as independently toggleable rows.
- Track controls form a fixed-width column on the left. Track lanes extend and scroll horizontally to the right.
- Track heights vary. The header and lane for a track must remain vertically aligned while scrolling.
- Track List and Clip List are supporting navigation surfaces, not a Live-style content browser.
- Universe is an optional overview above the rulers/tracks pane. It represents the shown track order and clip extents, exposes a framed current horizontal/vertical viewport, and lets a click relocate that viewport; it can be resized or hidden without changing project data.
- The MIDI Editor can appear as a pane inside the Edit Window in addition to the track pane. Mosh's bottom editor is therefore consistent with documented Pro Tools structure. Its local Track List contains only MIDI-capable tracks, independently controls which tracks contribute superimposed notes, and identifies an explicit edit target. Context notes are display-only; changing the target changes the one clip that receives note commands.
- Smart Tool is contextual. Its pointer affordance and action must follow media type and pointer region rather than act as a cosmetic toggle.
- In Spot mode, activating a clip through its Grabber intent opens a modal placement surface instead of beginning a free drag. The placement value uses the selected Time Scale and commits the clip Start through the normal move command.
- Tab changes navigation target according to Tab to Transients. When transient data is unavailable in Mosh, a clip-boundary fallback is honest and matches the documented disabled behavior.
- Track View is project-scoped shell state: audio tracks default to Waveform, MIDI/instrument tracks default to Clips, the main-keyboard Minus key toggles each track's two common views, and a separate disclosure exposes automation beneath the primary edit view.
- A source track's Sends section names the destination bus and exposes the level. Activating that bus opens its Aux return, whose channel owns the return fader, pan, output, and insert rack. Creating, assigning, editing, renaming, and deleting continue through the shared MoshOps command seam.
- The Zoom cluster follows Edit Modes and precedes Edit Tools. Horizontal zoom preserves the time beneath the pointer or viewport center; F5 Zoomer drag previews a range and fits it to the viewport. Audio-waveform and MIDI-note vertical scaling are independent and compose with the existing clip-gain display rather than rewriting gain or notes. Presets and media scales reset on project replacement, while zoom itself remains non-mutating view state.
- Zoomer has Normal and Single modes. Repeated F5 toggles the Zoomer mode; after one successful Single Zoom click, drag, or keyboard activation, Mosh restores the exact prior normal or Smart Tool state. Pointer cancellation and project replacement do not complete the pending operation.
- Lower-right controls mirror the toolbar's anchored horizontal scaling and proportionally resize every track header, primary lane, playlist row, and automation row. They stay reachable at compact widths and do not mutate project data.
- Marker Memory Locations are persistent project data. The Marker ruler creates and recalls them, while a floating list provides chronological numbering, search, edit, and removal without resizing the Edit timeline.
- Playlist comping preserves the main lane above timeline-aligned alternate takes. A non-current playlist supports either whole-take audition or a bounded phrase selection promoted into the main lane. In Waveform view, the same bounded selection now shows `Target: Main` and cycles previous/next takes with Command/Control+Shift+Up/Down while leaving the surrounding comp visible. Mosh represents each accepted range as ordinary split wave clips with copied take trees, so playback, undo, recovery, save/reload, multiplayer locks, JSONL capture, and later clip editing stay on the existing MoshOps seam. Arbitrary target designation and grouped-track application remain separate work; the latter must be atomic rather than a visual-only link.
- Punch recording uses the Edit selection as the in/out range and renders persistent PRE/PUNCH IN/OUT feedback across the timeline. The engine shares those in/out markers with its loop range but forbids loop playback and punch at the same time, so the shell sets the range with `loop:false` before enabling `punchInOut`. Pre-roll is the existing engine-native 0/1/2-bar count-in; it is visibly enabled in the transport and stored with the project. This is an intentional subset of Avid's arbitrary pre/post-roll and Dynamic Transport surface.
- Edit and Timeline selection are linked by default. Unlinking clones the shared span into a Pro Tools-local Timeline range: ruler gestures then change only playback/record scope, while clip or lane gestures change only editing scope. Relinking makes the current Edit span authoritative. Grid snaps through the session's piecewise tempo map and Option/Alt bypasses it. The original CSS boundary markers now expose Time Grabber/Smart Tool drag, Start/End slider semantics, Nudge keyboard movement, cancellation rollback, and project-epoch invalidation; the cross-lane highlight remains non-interactive feedback. Neither span becomes a project mutation until the producer explicitly invokes Punch or another command-backed action.
- The Edit-window counter cluster exposes a project-scoped Main Time Scale plus editable Start, End, and Length values. Forward Slash cycles Start → End → Length and Enter accepts a valid range; Escape and project replacement discard drafts. When Timeline and Edit are unlinked, these Edit-window fields continue to change only the Edit range, matching Pro Tools; Timeline markers and Punch retain the independent Timeline range. Absolute durations use the selected absolute scale. Bars+Beats duration entry uses the shell's existing sixteenth-resolution adaptation rather than claiming Pro Tools' 960-tick precision.
- Track and Edit selection are linked independently from Timeline and Edit selection. With Track/Edit linked, a lane interaction associates the Edit range with its track, while a vertical Selector/Smart Tool drag extends that association across every contiguous visible lane and selects the matching headers. Shift-click Track Names selects the visible range from the active header; Command-click on macOS or Control-click elsewhere toggles discontiguous Track Names. The same horizontal Edit span follows the exact linked set and renders one band per contiguous run. P/Semicolon with Edit Keyboard Focus, or Control+P/Control+Semicolon, moves the Edit span to one adjacent track and collapses a multi-track set as documented. Control+Shift+P/Semicolon adds the immediately adjacent visible track above/below the current outer edge; Option+Control+P/Semicolon removes the current top/bottom edge. Extension and removal preserve the horizontal span and exact intervening membership; Mosh keeps the final visible owner rather than creating a trackless Edit range because Avid's published descriptions do not specify the single-track edge case. Compatible Track View changes fan out across selected tracks. Shift+R/S/M/I acts on tracks containing the Edit selection, while Option/Alt+Shift-click on the matching header control applies to selected Track Names; every project change still uses the existing per-track MoshOps command and checks stale-project and applied-result envelopes. TrackInput is an explicit In/Auto toggle over Mosh's existing Off/Auto/In model. Shift+T and the labelled toolbar control toggle the relationship. With Track/Edit unlinked, the Edit range retains its lane set while header selection changes independently, and relinking restores every Edit-associated header. Mosh's canonical active-track store remains singular, so the operation edge owns the inspector only while Track/Edit is linked. Conductor-track Option/Alt selection and one-command native group edits remain stated gaps.

## Mosh adaptations and explicit non-claims

- The bottom status strip is a Mosh continuity affordance. No authoritative Avid status-bar contract was found, so it must not be presented as a pixel clone.
- The requested Classic theme uses a `#C0C0C0` base as a Mosh interpretation of older gray Pro Tools surfaces. It does not copy Avid textures, icons, logos, or artwork.
- Compact behavior will collapse or overlay supporting lists before shrinking the timeline below usability. This is a responsive adaptation for Mosh's WebView, not a claim about Pro Tools mobile behavior.
- MIDI superimposition is a bounded Mosh adaptation over the existing clip-local Piano Roll: the target clip owns the editor time window and controller lane, while visible overlapping MIDI notes from other tracks are projected into that window as disarmed context. The Track List exposes one target at a time because `editingClipId` is Mosh's canonical command owner; Pro Tools' multi-pencil-enable behavior and controller data from several tracks remain follow-ups rather than ambiguous multi-clip mutation.
- The first Spot dialog slice supports precise Start placement in the four shell time scales. Timecode follows the shell's existing fixed 30 fps ruler until project timecode-rate metadata exists; Sync Point and timestamp recall remain explicit adaptations until Mosh exposes those fields additively.
- Static per-clip gain uses `set_clip_gain`; dynamic clip-local gain uses the additive `write_clip_gain_curve` command. Both are behaviorally grounded by Avid's current Clip Gain walkthrough and use original Mosh DOM/CSS/SVG/canvas work. Dynamic breakpoint processing and per-segment waveform response are implemented without replacing track volume or static clip gain; non-linear curve-shape visualization remains outside this delivery.
- Track Views expose Waveform/Playlists/Volume and Clips/Notes, plus one secondary Volume lane. Playlists use Mosh's existing take tree for whole-take audition through `set_current_take` and range promotion through `promote_take_region`. Mosh adapts Avid's assembly gesture into drag-to-select plus a visible `↑ Main` confirmation, retaining keyboard access and preventing accidental promotion. Waveform view now exposes a textual `Target: Main` state and selection-scoped previous/next cycling through the same command; this is an accessible Mosh equivalent of V14's target/current color feedback, not a copy of Avid's blue/orange styling. Mosh does not yet claim arbitrary selectable targets, copy-versus-move choice, ratings, named playlist management, or atomic multitrack-group comping. Multiple simultaneous automation lanes, Elastic Audio Warp views, and direct per-note editing in the track row also remain deferred; MIDI note editing stays in Mosh's documented bottom editor.
- Sends use Mosh's existing `create_bus`, `add_send`, `set_send_level`, `remove_send`, `rename_bus`, and `remove_bus` commands. The engine currently implements post-fader sends only, so the shell labels that constraint and does not render fictional pre-fader, send-mute, send-pan, or send-automation controls. Aux returns are opened from the source inspector rather than a cloned Mix Window.
- Zoom uses original text/shape controls and UI-local view seams. Because Mosh also supports a computer-keyboard MIDI controller, R/T are claimed only while the Edit timeline owns focus; an armed QWERTY MIDI keyboard keeps its note key. The A−/A+, M−/M+, direct `1×` Single Zoom toggle, and percentage readouts are accessible Mosh adaptations of Avid's icon/pop-up controls. Track-height scaling uses four bounded project-scoped levels and preserves exact header/lane alignment rather than copying Avid control artwork.
- Memory Locations adapt Mosh's existing beat-anchored annotations, so marker names, colors, positions, undo, save/reload, multiplayer locks, and JSONL capture use the canonical command seam. Display numbers are derived from chronological order rather than stored as independent Pro Tools slot numbers. The first slice implements one Marker ruler, current-position create, exact/next/previous keypad recall, name/number search, edit, and removal. Multiple marker rulers, track markers, edit-selection/zoom/track-visibility recall, advanced property filters, batch management, and import remain explicit gaps.
- Punch and pre-roll reuse `set_transport`, `set_record_options`, and `set_count_in`; no snapshot is mutated. Mosh's `Pre Off/1 bar/2 bars` selector is an accessible compact adaptation of Avid's separately enabled numeric field, and the yellow/red flags are original primitives rather than Avid art. Browser state can prove the command sequence and visual feedback but not audible context, monitor switching, or the recorded file's exact boundaries; those remain native physical-device acceptance. QuickPunch, arbitrary numeric pre/post-roll, post-roll, and Dynamic Transport are not claimed.

## Design consequences

- Direction: dense operational editor, low visual variance, minimal decorative motion, strong tonal hierarchy.
- Signature: a dimensional two-tier editing toolbar above a ruler stack, with the left track controls visually locked to the scrolling lane field.
- Color story: charcoal surfaces (`#1E1E1E` through `#2D2D2D`), cool gray text (`#C0C0C0`), selection blue (`#4A90D9`), and grid gray (`#3A3A3A`).
- Asset rule: reuse Mosh's existing icon primitives and rendered clip content. Do not trace or reproduce Avid icons or branded graphics.
