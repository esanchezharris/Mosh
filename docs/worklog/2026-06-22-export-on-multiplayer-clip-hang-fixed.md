# Export-on-multiplayer-clip hang FIXED (2026-06-22)

_Working note, 2026-06-22. Moved verbatim out of CLAUDE.md; content unchanged._

**Export-on-multiplayer-clip hang FIXED (2026-06-22).** Long-standing bug: `export_audio` (and playback) spun forever (`RenderTask::runJob → graph::getNodes → ArrangerLauncherSwitchingNode`) when the edit held a wave clip with a **relative** source ref — produced by `mp_commit_track` (by-hash), or `relink_clip`/`consolidateAudioInto` on an **unsaved** edit. Root cause: Tracktion's `setToDirectFileReference(file,true)` stores the rel path via `getRelativePathFrom(editFileRetriever())`, and when the edit file doesn't exist on disk yet JUCE treats that *file* path as a *dir* → emits an extra `../` (`"../audio/by-hash/x.wav"`); Mosh's `filePathResolver` resolved against the file's PARENT → landed one level too high → non-existent path → clip read source-missing → render recursed. (Save-as/consolidate worked only because the edit file existed → no `../`.) Fix = ONE place: `MoshEngine::wireEditResolvers` filePathResolver now tries the parent base first (legacy/correct refs), then falls back to the edit-file-as-dir base (matches how the string was computed), else the unchanged default — additive, fixes export AND playback. Reproduced MP-free via `relink_clip` to a co-located source (relative ref → hang); fixed → completes + non-silent. Regression guard: `verify.py` `check_relative_ref_export` (timeout-protected). Also made the **selftest hermetic to locally-installed RAVE models**: a new `MOSH_ENABLE_TRANSFORM=0` gate (`transform_adapter.available()` + `runSelfTest` setenv + verify.py fake-transform check) pins the deterministic fake transform regardless of `~/AI/rave-models` contents (the real path stays covered by `verify.py --rave`). Verified: selftest **887/887 ×3** (with 17 real models installed), Catch2 162, verify.py 5/5. Adversarial review: 0 correctness findings. (The prior playtest-prep notes on branch `claude/playtest-prep-0621` documented this as engine-level/deferred with a MIDI-only workaround — now resolved.)
