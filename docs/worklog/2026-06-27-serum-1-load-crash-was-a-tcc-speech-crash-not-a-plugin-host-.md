# "Serum 1 load crash" was a TCC speech crash, not a plugin-host crash (2026-06-27)

_Working note, 2026-06-27. Moved verbatim out of CLAUDE.md; content unchanged._

**"Serum 1 load crash" was a TCC speech crash, not a plugin-host crash (2026-06-27).** A reported in-process crash loading the ORIGINAL Serum (com.xfer.serum.VST3) — "Serum 2 fine, dies right after Generating waves" — turned out NOT to be Serum at all. Every recent `~/Library/Logs/DiagnosticReports/Mosh-*.ips` SIGABRT is a **TCC privacy kill** (`__TCC_CRASHING_DUE_TO_PRIVACY_VIOLATION__`, termination ns `TCC`): the app calls `[SFSpeechRecognizer requestAuthorization:]` (the always-on/hands-free voice, `src/voice/NativeSpeech.mm:66` via `voice_listen_start`) while the bundle Info.plist is **missing `NSSpeechRecognitionUsageDescription`** → macOS hard-kills the process. The identical crash fires with **Serum 1, Serum 2, AND no plugin loaded** — Serum was incidental (just resident in-process; no Serum/JUCE-hosting frame on any live stack). So `block_plugin` (blocks loading — but the crash needs no plugin) and OOP hosting (isolates the plugin — but the abort is in the MAIN process's voice subsystem) would BOTH have been wrong fixes; they remain right for the *separate* genuine plugin-teardown class (the SIGSEGV-in-`runSelfTest` crashes). Root cause of the missing key: the `plutil -replace` that injects speech/camera/bonjour was a **Mosh-target POST_BUILD**, which only runs on a relink → skipped on up-to-date/UI-only/deploy builds, and `run-mosh.sh deploy` did a `cp -R` with **no plist check** → it shipped a TCC-crashing **/Applications/Mosh.app** (verified missing the key; mic key present). Same root class as the documented "JUCE PLIST_TO_MERGE is Xcode-only" note. **Fix (this branch):** keys moved to ONE source (`cmake/InjectInfoPlistKeys.cmake`, fail-closed — FATAL if the key is absent after inject) run from BOTH the POST_BUILD and a new always-run `MoshFixInfoPlist ALL` target (mirrors `MoshStageUI`, added to the 2 macOS app presets); `install_app` re-injects+verifies on deploy; `gate.sh` asserts the built bundle carries the key. **Verified:** build runs both the POST_BUILD and the backstop; a no-relink rebuild after deleting the key RE-INJECTS it (the regression the old code failed); the `-P` script is fail-closed on bad input; the already-deployed /Applications/Mosh.app was hotfixed (`plutil -replace` + ad-hoc deep re-sign → valid). C++ untouched.
