# Per-feature venvs moved OUT of iCloud (2026-07-03)

_Working note, 2026-07-03. Moved verbatim out of CLAUDE.md; content unchanged._

**Per-feature venvs moved OUT of iCloud (2026-07-03).** In-tree `service/<name>/.venv` sat under iCloud-synced ~/Documents and corrupted twice in two days (onnxruntime, then basic_pitch silently vanished → /transcribe 503, FCPE skeleton upgrade lost — no error at install time). All 8 venv-creating setup scripts (transcribe / skeleton / whisper / phonology / sketch / transform / flp / sft) now default to **`~/Library/Mosh/venvs/<name>`** (override root: `MOSH_VENVS_DIR`); the `.env` files next to each script remain the **single source of truth** (run.sh / server.py / parseFlp.ts seams unchanged). Re-runs are CHEAP: a healthy venv just re-validates imports + rewrites the .env (transcribe 2.8s, phonology 0.03s vs a pip run every time); `--reinstall` forces the full install/top-up; the legacy in-tree `.venv` is auto-removed once the new location validates. `server.py`'s conventional-default fallback (used when the .env is absent — e.g. the deployed bundle, which carries no .env files) now prefers `~/Library/Mosh/venvs/<name>` then legacy in-tree. Golden: `service/scripts/venv_locations_test.py` (static conformance + runs each script against a shim venv with a booby-trapped `uv` — any installer touch on a healthy re-run fails; 3× deterministic). Migrated this Mac: sketch + phonology rebuilt at the new root, main-checkout .env files updated, ALL in-tree venvs deleted; smokes green (/health transcribe·sketch·skeleton·phonology all true, /transcribe → 4 notes, /skeleton_spec → real skeleton spec, /get_rhymes → real cmudict + palette merge). Also fixed the missing skeleton .gitignore block (`.skeleton.env` was untracked noise). Out of scope on purpose: `setup-sa3.sh` (venv already external at ~/AI), `setup-sft-cuda.sh` (remote CUDA box), `teardown/.venv` (no setup script — dev lane).
