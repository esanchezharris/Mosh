# Ableton-style "easy warp" landed (2026-07-17)

_Working note, 2026-07-17. Moved verbatim out of CLAUDE.md; content unchanged._

**Ableton-style "easy warp" landed (2026-07-17).** The engine already had whole-clip auto-tempo (`set_clip_warp`, Tracktion SoundTouch) but it was a hidden Inspector toggle that defaulted `sourceBpm` to the project tempo (a 1:1 no-op — imported loops never snapped to grid). Added the *easy* layer: (1) `stretch_clip {clipId, length|bars}` sets a wave clip's WARPED length by deriving `sourceBpm` (`warpedLen = sourceLen × sourceBpm / projectBpm`; bars branch: `sourceBpm = bars×beatsPerBar×60/sourceLen`) + `setPosition` to fill the span — powers the drag-to-stretch gesture and Inspector "Fit N bars / ½× / 2×"; (2) `detect_clip_bpm` — read-only offline BPM estimate (onset-envelope autocorrelation over 70–180 BPM, **pure C++**, deterministic in `--selftest`, no service) → `{bpm, confidence}`; (3) a `detect:true` flag on `set_clip_warp` auto-locks a loop to grid on enable (GUARDED — default path byte-identical, existing warp selftest untouched). UI: `A.STRETCH` gesture (⌘+edge-drag on a wave clip, more-specific than TRIM) in `gestureTables.ts`/`ClipView.tsx`/`clipDrag.ts`; a `≈` warp badge + `warped` class on warped clips; WarpTab Detect/Fit/×2÷2 helpers (progressive disclosure — only when warp is on). Mock parity in `bridge.mock.ts`; `stretch_clip`/`detect_clip_bpm` in the agent catalog (`set_clip_warp` stays UI-only, as before). Per-transient warp MARKERS remain deferred. Contract rows in `docs/02_MOSHOPS_CONTRACT.md`; engine APIs in `docs/ENGINE_API_NOTES.md`.
