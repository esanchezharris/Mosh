> caught a genuine intermittent `--selftest` SIGSEGV (`rc=139`, 2 of 3 runs; see CI runs

> `required_status_checks` was never enabled on `main` (HTTP 404 "Required status checks not

**Arrangement/editing throughput window — 18 PRs, #410–#427 (2026-07-18).** A long autonomous run against the DAW-conformance backlog and the open-PR queue. **Native feature lanes:** #410 the composed editing lane (clip inspector gain/mute/rename, clip fades, export range/section + delay-tail, per-track stem export, count-in/pre-roll), #414 automation (`set_track_automation_mode` write-mode recording + `write_automation_curve` bulk authoring), #417 clip-ops (reverse, auto-crossfade, non-destructive normalize), #420 master-bus plugin hosting, #424/#425 opt-in ripple delete + clip loop region, #426 metering (see METER-001). **Scale lock** (#427, reality-model **invariant 88**) closed the last cheap conformance gap: an INPUT AID on the snap-to-grid precedent — the piano roll resolves the pitch BEFORE issuing `add_note`/`set_note`, so "never rewrites existing notes" is structural rather than best-effort, and it needs **zero** engine/command/snapshot change. `musicalKey.ts` had long claimed to be "kept IN LOCKSTEP with vendor/voice.js" while carrying the tables only as prose comments; it now carries `NOTE_PC`+`SCALES` as data and `musicalKey.test.ts` **parses voice.js and asserts they match**, so the roll shades exactly the scale Moshi sings and the native `set_key` 6-mode domain is honoured rather than quietly widened.
