# METER-001 — v2 track/master level meters + a real coverage bug fixed (2026-07-18)

_Working note, 2026-07-18. Moved verbatim out of CLAUDE.md; content unchanged._

**METER-001 — v2 track/master level meters + a real coverage bug fixed (2026-07-18).** Per-track metering (Wave 9) was already shipping — `ensureTrackMeter` appends a `te::LevelMeterPlugin` post-fader, decimated onto the 30 Hz `"levels"` event — but it was reachable from only ONE code path, `enable_all_meters`, called ONCE at UI `init()`. **Coverage bug confirmed:** any track created mid-session (`create_track`, `import_clip`/`paste_clip` auto-create, `add_midi_clip`/`add_drum_pattern` auto-create, `create_bus`, `accept_render`'s "Neural Renders" lane — all funnel through the shared `createAudioTrack` helper, `src/moshops/MoshOps.cpp`) never appeared in `levels`, silently, until the app relaunched. **Fix — NOT inside `createAudioTrack` itself:** `ensureTrackMeter` appends at the pluginList's CURRENT end, so calling it at track-creation time (before a same-command instrument/AuxReturn/volume insert) would leave the tap ahead of those plugins — silently mismeasuring the track (an instrument-fronted tap sees pre-instrument silence). Instead, each of the 7 call sites now calls `ensureTrackMeter` itself, placed AFTER any same-command pluginList setup: `cmdCreateTrack` (audio+drum), `importWaveFileToTrack`, `cmdPasteClip`, `cmdAddMidiClip`, `cmdAddDrumPattern` (resolved via `outTrackId` so it covers both the per-lane-replace and new-track branches), `cmdCreateBus` (after the AuxReturn + volume inserts), and `accept_render`'s Neural-Renders-lane resolution. Calls are unconditional (not just on the "track==nullptr" branch) so they **self-heal** any track a mutating command touches, even one whose meter was explicitly disabled or pre-dates this fix — proven in `--selftest`. Deliberately **NOT** metered: `findOrCreateHiddenRenderTrack` (excluded from `snapshot()` entirely — no UI can ever read it). Bus/return tracks and the hidden-beneath lane are still excluded from the v2 arrangement UI (matches classic `Mixer.tsx`'s `!t.isReturn` filter), but are metered natively for consistency with what `enable_all_meters` already covered. **v2 UI:** a new `TrackMeterBar` (`ui/src/v2/lanes/TrackLaneList.tsx`) sits beside Mute/Solo in `TrackLaneHeader`, reusing the classic shell's `<Meter>` (`ui/src/ui/Meter.tsx`) verbatim — same rAF-imperative-DOM ballistics/clip-latch, so the widget never triggers a React re-render of the track tree — under a new sizing-only `.v2-meter` class (`shell.css`; the underlying `.meter`/`.mbar`/`.mmask` rules in `mosh.css` are global and untouched). A master-level readout (`<MasterMeter/>`) was added to `RightRail`'s existing `MasterCard` (next to the Vol/Pan faders) as the v2 master-meter surface. **Corrected a stale/misleading CLAUDE.md claim** (Stage 2 bullet) that real audio level meters were still deferred for lack of a `VolumeAndPanPlugin` level-tap — true of that plugin specifically, but Wave 9 solved it with a dedicated `LevelMeterPlugin` a year of working-notes ago; the bullet had gone unnoticed and misled this very session's initial read. **Note for a future pass (not fixed here, pre-existing, out of scope):** a meter is only guaranteed post-fader at the moment `ensureTrackMeter` runs — a plugin loaded later via `cmdLoadPlugin` (which appends, like the meter itself) can land AFTER an already-present meter, making the reading pre-that-plugin. This already applies to every track metered via `enable_all_meters` today; not introduced or worsened by this fix.
